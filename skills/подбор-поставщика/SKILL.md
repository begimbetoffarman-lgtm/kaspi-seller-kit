# Подбор поставщика на 1688

Вход: товар из папки `Products/` вашей базы (путь к базе записан в `CLAUDE.md` проекта,
строка «База товаров») или ссылка на карточку Kaspi.
Выход: совпавший вариант поставщика, цена, маржа, что не проверено.

**Главное правило: цена считается только по варианту, который по фото и характеристикам
совпал с Kaspi.** Типичная ошибка: по ключевым словам взяли чужой товар (шаль вместо
массажёра с «руками»), посчитали красивую маржу, а фото не сравнили. Расчёт получился по другому товару.

**Стиль ответа пользователю: коротко и ясно.** Таблица и 3–5 строк выводов. Без длинных
пересказов шагов. Подробности только по запросу.

## 0. Что должно быть установлено

- `1688-cli` (`npm i -g 1688-cli`) и вход в аккаунт 1688 по QR-коду. Проверка: `1688 --help`.
  Нет входа: скажи пользователю и остановись, логин делает только человек.
- Встроенный браузер или Claude in Chrome для страниц Kaspi.

## 1. Эталон Kaspi

1. Прочитай карточку в `Products/`: цена Kaspi, комиссия, ссылка. Курс из карточки не брать.
2. Открой страницу Kaspi в браузере. Адреса фото:
   `await new Promise(r=>setTimeout(r,1500)); [...new Set(document.documentElement.innerHTML.match(/https:\/\/resources\.cdn-kaspi\.kz\/img\/m\/p\/[^"'\s)]+/g))]`
   Берёшь размер `gallery-medium`. Характеристики: `.specifications-list__el`.
   Страница не открылась: скажи и попроси скриншот.
3. Посмотри **все** фото. Запиши признаки: форма, материал корпуса, цвет, кнопки (сколько,
   где), дисплей, порт, подогрев, комплектация, мощность и ёмкость из текста.

## 2. Поиск на 1688

В PowerShell команды только через `&` (имя с цифры читается как число). Вывод в файл
(`Out-File -Encoding utf8`), иначе иероглифы ломаются.

```bash
& 1688 search "<китайские слова по признакам эталона>" --max 15 --sort best-selling --exclude-ads --json
& 1688 offer <id1> <id2> <id3> --json
```

- `search` цен не даёт. Цены, варианты (`skus`), вес (`packageInfo`), фото (`images`,
  `skus[].image`) есть только в `offer`.
- Бери кандидатов по названию и фото, не только по продажам. Если меньше половины выдачи
  про товар, сузь слова (максимум 2 повтора).
- Одинаковое название при разной форме (стоящий и сидящий астронавт) это разные товары.

**Поиск по фото, порядок:**
1. `& 1688 image-search <фото Kaspi>`: одна попытка за сессию. Может не работать:
   страница загрузки показывает ползунок. Не прошла, больше не повторять.
2. Яндекс по картинке: `https://yandex.kz/images/search?rpt=imageview&url=<url-encoded фото>&text=site:1688.com`.
   Даёт слова («Кажется, на изображении») и страницы-категории 1688, прямых
   ссылок на товары почти нет. Это подсказка, не результат.
3. Основной путь: поиск по словам и сверка фото (шаг 3).

**Темп и антибот:** на товар не больше ~2 поисков и одной пачки `offer` (3–4 id). Ползунок,
`punish` или `STABLE_LOCATOR_NOT_FOUND`: сразу остановиться, не повторять, сказать
пользователю (остывает часами). Капчу не обходить. Прямая ссылка на `detail.1688.com/offer/<id>.html`
безопаснее поиска. При блокировке не выдумывать данные.

## 3. Сверка (обязательно)

Для каждого кандидата открой главное фото и фото вариантов (`skus[].image`) и сравни с
эталоном по признакам шага 1. Читай названия вариантов (`specs`): подогрев, дисплей, мощность.
Вердикт: **совпало** / **не совпало** (чем отличается) / **не проверить по фото** (чего не видно).
«Тот же товар» писать только при «совпало» по форме, материалу, кнопкам/дисплею, функциям.

Пример сверки: у Kaspi массажёр с двумя кнопками сверху и без дисплея. Значит подходят варианты
1688 без дисплея, а варианты с `数显` (цифровой дисплей) нет.

## 4. Расчёт

**Курс юаня живой, не из памяти и не из карточки.** Источник по умолчанию:
https://ifin.kz/exchange/aktobe/CNY (колонка **«Продажа»**, мы покупаем юань). Если вы в другом
городе, откройте страницу своего города на ifin.kz (замените `aktobe`). Возьми лучший
(минимальный) и типичный курс, дату обновления. Считай по типичному. Страница не открылась:
спроси курс у пользователя, старый не подставляй.

```
закупка_₸ = цена_¥ * курс
карго_₸   = вес_кг * тариф_за_кг
комиссия  = цена_Kaspi * комиссия%
прибыль   = цена_Kaspi - закупка - карго - комиссия
```

Тариф карго, налоги, доставку до покупателя даёт **пользователь**. Нет их: посчитай две
ставки карго и назови допущением. Вес: реальный и объёмный (Д×Ш×В/5000, это типичная
формула, у вашего карго может быть иная). НДС на комиссию, налог, реклама, возвраты не
учтены, пока не даны. Так и пиши. Полная юнит-экономика с комиссиями категорий:
навык `tovarka-agents` (скрипт `scripts/unit_economics.py`).

## 5. Отчёт (коротко)

1. Эталон Kaspi: ссылка, 3–5 главных признаков.
2. Таблица кандидатов: вариант, цена, вердикт сверки.
3. Прибыль по совпавшим вариантам и допущения одной строкой. Курс с источником и временем.
4. Что не проверено, что спросить у поставщика.
5. **Ссылки (обязательно по каждому рекомендованному):** предложение
   `https://detail.1688.com/offer/<id>.html`, фирма (`supplier.name`), магазин
   (`supplier.shopUrl` из `search`), совпавший вариант, фото варианта. Без них отчёт не готов.

Не писать поставщику, не заказывать, не платить без отдельной команды. Базу (Obsidian) не
менять, пока не попросят (тогда: `supplier`, `buy_price_cny`, `weight_kg` в карточке и
заметка в `Suppliers/`).
